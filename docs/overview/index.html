The control plane for AI agents

Frameworks help you build an agent. AgentKitAI is the layer around it in production — observe what it did, govern what it's allowed to do, remember across sessions, collect human input when it's stuck, and evaluate that it still works. The through-line across every product is provenance & compliance: tamper-evident audit, signed evidence, and EU AI Act / OWASP-LLM framing — so an agent's behavior isn't just logged, it's cryptographically defensible.

Everything is MIT/ISC-licensed, self-hostable, and MCP-native — each service is also a Model Context Protocol server, so Claude Desktop / Cursor / any MCP client can drive it. Distribution is unified under the @agentkitai/* npm scope (PyPI for the Python services, ghcr.io/agentkitai/* for Docker, io.github.agentkitai/* in the MCP Registry).

What ties it together

  1. Provenance is the product. Hash-chained audit (Lens), OWASP-tagged decisions (Gate), signed evidence packs (CLI), JWT-VC receipts (FormBridge), tamper-evident eval evidence (Eval) — defensible records, not just logs.
  2. Real integrations. Eval↔Lens (sessions→tests, results→audit), Guardrails (Lens metrics→Gate policy), shared @agentkitai/auth + @agentkitai/pricing libraries, CLI-minted identities used across services.
  3. MCP-native throughout. Every core service is also an MCP server (~22 Lens + 40 Lore + 10 Gate + per-intake FormBridge tools) — an LLM agent can operate the control plane itself.
  4. Tokenless, reproducible distribution. Unified @agentkitai/* scope, 20 OIDC Trusted Publishers, MCP Registry entries current — supply-chain hygiene matching the compliance story.
In one line: AgentKitAI is the governance, observability, memory, and evaluation plane you wrap around any agent so it's auditable, controllable, stateful, and testable — independent MIT-licensed services that each stand alone but compose into one self-hostable control plane.
